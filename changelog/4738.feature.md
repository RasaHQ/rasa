Added a minimum pacing delay for voice channels to prevent responses from starting too abruptly after an filler message from the ReAct agents (e.g. "Let me check on that."). If the next response is ready before the configured delay has elapsed, the channel waits for the remainder of the gap before beginning to stream audio.

The delay applies after a streaming filler message from an MCP agent with `enable_filler_messages: true`, where tool execution immediately follows.
