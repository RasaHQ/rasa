Added a Copilot response evaluation pipeline to assess response quality on faithfulness and completeness dimensions using LLM-based judges.

The pipeline includes:
- `CopilotResponseEvaluator` orchestrator that coordinates claim extraction and concurrent judge evaluations
- `BaseLLMJudge` abstract base class providing OpenAI structured-output API calls, semaphore-based concurrency control, and unified error handling
- `FaithfulnessJudge` to evaluate whether claims are factually grounded in evidence sources (documentation and code)
- `CompletenessJudge` to assess whether responses fully address user requests given conversation context
- `ClaimExtractor` to decompose responses into atomic, verifiable claims with importance labels
- Configurable parameters (via `CLAIM_EXTRACTOR_*`, `FAITHFULNESS_JUDGE_*`, `COMPLETENESS_JUDGE_*`, `MAX_CONCURRENT_EVALUATIONS`, etc.) cover models, timeouts, max tokens, and per-component concurrency.
- Langfuse runners already execute items with their own per-item concurrency, so these env-based limits mostly matter for non-Langfuse orchestrators.
